## 1. 项目定位与适用范围

DeepSeek Remote Workspace 是 DeepSeek Harness 的实验性远程工作区插件，集中处理 SSH/SFTP、FTP/FTPS 文件操作，并经 SSH 支持部分 Linux 系统查看和管理。它不是 Linux 发行版、远程服务器安全产品、完整备份系统，也**不会自动把 Harness 的原生本地文件和命令工具替换成远程工具**。

- 适合：个人对自有隔离测试主机进行学习、协议兼容性测试、非生产文件操作与功能评估。
- 不允许：商业使用、商业环境使用、任何公司、机构、学校、实验室、研究组或其他组织性使用，包含免费内部测试。
- 风险：删除文件、误执行命令、修改服务、失去连接、泄露凭据、下载覆盖和数据损坏等；使用前自行确认访问权限并做好独立备份。
- 状态：曾运行自动化测试，但不能因此声称已完成真实 Windows Desktop、各类 FTP 服务器或宿主身份鉴权的全面验收。

## 2. 安装、构建与首次验收

### 2.1 环境

- 兼容的个人 DeepSeek Harness 开发或运行环境。
- 从源码构建需要 Node.js **20.11 或更高**及项目使用的 pnpm；Host 还必须提供插件依赖的 Harness 接口/Peer 依赖。
- 优先在单独的 Harness 测试 profile 中验证，不要覆盖正在执行远程操作的实例。
- 依据用途选择 **Host-only 安全包**或**实验性 Web UI 完整包**，不要假设任意宿主版本都支持 UI 热重载。

### 2.2 安装和首次验收流程

1. 从有权发布的官方渠道取得与当前版本匹配的插件安装包；核对版本及 SHA-256（若发布方提供）。
2. 在隔离 profile 中通过 Harness 支持的插件管理方式安装和启用插件。具体操作因宿主版本而异；以实际 Harness UI 为准。
3. 打开插件管理界面，添加 SSH/SFTP 或 FTP/FTPS 连接配置。使用测试主机和最小权限账号。
4. 先测试连通性与身份，再列出目录；SSH/SFTP 可继续测试受控读写，FTP/FTPS 不测试 Shell。
5. 建立插件托管远程会话，在授权确认后进行一次小文件上传与下载，再测试取消、断线和停用。
6. 实际 Web UI 无法激活或热重载失败时，先停用插件并排查宿主日志，必要时完整重启 Desktop。

### 2.3 从源码验证与打包

在项目根目录、且满足依赖条件时执行：

```bash
pnpm run verify
pnpm run pack
pnpm run pack:ui-experimental
```

`verify` 为项目测试入口；`pack` 与 `pack:ui-experimental` 分别用于 Host-only 与实验性 Web UI 打包。运行前核实当前仓库 `package.json` 中脚本仍保留此名称；Harness 私有依赖需要与实际宿主环境匹配。打包完成后实际检查 `npm pack --dry-run` 或对应归档清单，不把测试通过等同于依赖许可证合规。

### 2.4 Windows CLI 隔离验收示例

在已有 Harness CLI 的个人测试环境中，停止目标测试 profile 后，可按以下命令安装与查看配置（路径和文件名仅为示例）：

```powershell
dsh plugin --profile rw-test add "D:\Downloads\dsh-remote-workspace-0.5.26-ui.1.tgz"
dsh --profile rw-test --dump-config
dsh --profile rw-test
```

优先使用新 profile；首次启动核对插件 UI、服务器连接列表、SSH 指纹、凭据恢复、目录权限及操作审批。若 `web boot` 失败，先停用插件；不要以删除整个 profile 或凭据仓库代替故障排查。

插件数据通常位于 profile 的 `.plugin-data/dsh-remote-workspace`，历史安装可能沿用用户目录的 `.dsh/remote-workspace`；切换 `dataDir` 不代表自动迁移旧连接和凭据。配置目录前应备份并确认目标路径属于该插件。

## 3. 连接配置与 AI 会话授权

### 3.1 协议与凭据

| 能力 | SSH/SFTP | FTP/FTPS |
| --- | --- | --- |
| 浏览、上传、下载远程文件 | 支持 | 支持 |
| 插件托管远程会话工作区 | 支持 | 支持 |
| SSH 命令、交互终端 | 支持（需授权） | **不支持** |
| Linux 监控、服务/进程操作 | SSH 路径下按权限提供 | **不支持 SSH 管理能力** |
| 本地项目与受限远程目录绑定 | 支持，需用户确认 | 当前不支持 |

不要在 AI 聊天窗口提交服务器密码、私钥或其他凭据。凭据应从插件管理界面的可信输入途径配置。连接前验证真实主机身份，避免盲目接受改变的 SSH Host Key。

### 3.2 AI 权限边界

AI 工具实行**默认拒绝**。满足以下条件才可能访问远程：

1. Harness 提供可信的当前会话及工作目录身份。
2. 当前会话位于插件托管的远程工作区，或本地项目具有用户通过管理界面确认的可信绑定。
3. 服务器身份、工作区/绑定目录和授权状态均匹配。
4. 完成连接审批及必要的高风险操作审批。

普通聊天无法仅通过输入服务器 `profile` ID 获得远程访问权。远程托管工作区仅可访问绑定服务器。本地项目绑定仅开放限定在绑定远程子目录内的 `remote_project_*` 工具及少量连接/状态元数据，不能切换到普通无限制的远程文件工具。

本地项目的 `.harness-remote.json` 不能单独成为授权凭据；还必须匹配插件私有的可信绑定记录。早于 v0.5.23 的本地项目绑定需在插件 UI 重新确认一次。删除绑定、更换服务器或修改关键目录后，应当使旧授权失效。

### 3.3 连接审批与命令审批

- 保存的密码或 SSH 密钥**不代表** AI 被自动授权连接；必须通过可信的连接审批。
- 未保存凭据时，用户应在插件 UI 中手动连接，而不是在聊天消息中提供口令。
- 命令执行、项目写入和其他高风险操作依各自审批策略执行。取消、拒绝或状态变化时必须拒绝继续操作。
- SSHFS/native 挂载场景仍涉及宿主本地工具绕过风险；不能仅凭本 Wiki 假设所有第三方工具都被拦截。请在实际 Harness 环境独立验证隔离。

### 3.4 手动连接的有效范围

未保存可恢复凭据时，在插件连接管理界面输入密码并执行「手动连接供 AI 使用」；实际服务器认证通过后，仅会产生短期、单次会话领取的验证记录。返回聊天选择「已手动连接」不构成单独凭据。手动验证可能在约两分钟后失效，不能跨聊天复用；断开授权、更改连接或重启 Host 后须重新验证。

凭据混淆模式可逆，不能视为加密。Windows 上受支持的 DPAPI 保护依赖当地系统配置和实际登录账户；不要将密码、私钥或完整连接配置发送到问题报告。

## 4. 远程文件管理和传输

### 4.1 基本操作

文件页提供目录浏览、搜索、打开/编辑、上传、下载，以及按权限开放的创建、重命名、删除操作。删除或覆盖属于高风险行为，应在独立备份后执行。

文件页使用“常用操作 + 更多操作”工具栏，并以小问号或悬浮提示解释操作；实际呈现以具体构建为准。

### 4.2 拖拽上传

1. 在文件管理页打开目标目录。
2. 把一个或多个**文件**拖入指定上传区域，确认目标路径及文件列表。
3. 观察传输进度；需要停止时点击该任务的取消操作。
4. 取消后检查状态及远程目标；不要假定已提交的远程更改能自动回滚。

**边界：** 单文件上限 **128 MiB**；传输采用约 **192 KiB** 分块。上传同名文件默认不自动覆盖。当前不支持文件夹递归拖拽、断点续传或拖出到桌面。不要把浏览器根区域的防导航拖放拦截误认为上传目标。

### 4.3 下载及中途取消

异步下载流程可在服务器仍读取文件时取得传输标识并请求取消；后端在传输任务退出后清理关联临时文件。浏览器支持 File System Access API 时可边读取边写入目标；否则使用 Blob 兼容路径，可能带来较高的内存占用。

**“可随时请求取消”不等于“网络操作即时终止”。** 底层网络等待、服务器状态或文件提交阶段可能产生延迟。取消前已经保存在本地或远程的数据需要用户自行核对。对重要文件建议再校验文件大小和哈希。

### 4.4 断线、失败与残留

- 连接断开时核查上传、下载是否完成，不应把半成品当作成功结果。
- 遗留传输缓存应由插件的临时文件回收流程处理；异常崩溃产生的旧缓存可能要在下一轮清理中处理。
- 遇到未识别残留时优先报告，而不是删除来源未知的文件。

## 5. Linux 监控、进程及服务

通过已授权 SSH 连接可按需查看 CPU、内存、磁盘、网络、进程及部分 systemd 服务信息。进程信号和服务启动、停止、重启等会修改目标状态，可能引起业务中断。

- 只在**个人隔离实验主机**执行；本许可禁止组织和生产环境使用。
- 避免把监控信息视为完整运维告警系统；显示依赖目标主机权限、工具、系统兼容性和采样时点。
- 对进程 PID、服务单元名称、预期影响进行二次确认；固定格式的确认字符串只保护误操作，**不能代替调用者身份鉴权**。
- 不支持通过 FTP/FTPS 管理 SSH 进程和 systemd 服务。

### 5.1 数据口径及边界

- CPU 使用率由 `/proc/stat` 采样估算；系统负载显示 1/5/15 分钟值。
- 磁盘信息来自 `df -Pk`，网卡接收/发送字节来自 `/proc/net/dev`，是自启动以来的累计量而非瞬时带宽。
- 进程列表基于 `ps`，默认按 CPU 展示有限数量（通常最多 200 项），其 `%CPU` 不是逐秒采样。
- systemd 服务列表仅对支持该服务管理器的主机有效（通常最多 160 项）。
- TERM 允许目标进程自行退出；KILL 强制终止。发送前核对 PID，避免 PID 被复用；插件不主动通过 `sudo` 提权。

只读监控按需采集，默认不进行持续后台轮询或自动修复。无 `/proc`、`ps`、`systemctl` 的环境可能不支持这些功能。

## 6. 插件生命周期、卸载与清理

### 6.1 停用或更新

插件停用时，应释放**插件自己持有**的 Host 工具、API 路由、SSH 会话、临时密码和会话授权，不应该关闭或删除其他插件的资源。Host 是否完整支持插件热重载取决于 Harness 版本；功能异常时按实际宿主恢复流程处理。

### 6.2 卸载数据范围

插件私有的连接配置、授权记录、传输临时文件等可能由专用清理动作识别并移除。删除前应列出清理目标、获得明确确认、避免模糊路径和跨插件删除。遇到未知残留必须如实报告，不能宣称彻底清空。

下列内容**不属于安全的一键清理范围**：远程服务器中的文件、用户已下载的文件、本地项目内的自有文件、Harness 历史聊天及其他插件/系统数据。卸载前应自行备份需要保留的连接配置。

### 6.3 持久状态和清理限制

关闭页面不等于停用 Host 插件。停用插件通常释放自身工具、路由、交互 SSH 会话及临时授权，但不会删除保存的连接资料或远程文件。Host 停止不能保证撤销已经送达服务器的命令或已经提交的传输，更新前必须主动停止正在执行的操作。

插件审计日志采用限制容量的轮转方式（通常约 4 MiB 活动文件和一个历史轮转文件），不能作为长期归档。清理前应导出确有需要的记录。

## 7. 架构、信任边界与开发维护

项目包含 Harness Host 侧远程工具、Web UI、服务器 API、连接适配、工作区/项目绑定、授权门禁、文件传输会话和插件资源生命周期管理等模块。主要模块及信任边界：

```text
DeepSeek Harness (Host / trusted agent context)
  ├─ AI tools -> trusted session/binding gate -> user approval -> remote operations
  ├─ Plugin API -> host-auth boundary -> Web UI actions
  └─ plugin lifecycle -> plugin-owned resource disposal

Remote operations
  ├─ SSH/SFTP: files, commands, terminal, Linux monitoring
  └─ FTP/FTPS: files and transfers only

State
  ├─ connection profiles / optional stored credentials
  ├─ trusted project binding records
  └─ short-lived connection authorization / transfer sessions
```

**核心边界：** Web 管理路由必须依赖真实宿主身份鉴权与请求隔离，不能因为 AI 的绑定门禁已经收紧，就默认 Web API 也得到了身份鉴权。Host 对原生或第三方本地工具的 SSHFS 隔离覆盖度也要单独测试。

**贡献与维护：** 项目采用限制性源码可查看许可证，贡献、复制、改编及再分发都必须满足权利人授权；提交外部代码前核对其原许可证及版权。不要删除安全门禁、隐私清理的谨慎检查或第三方许可文本以追求代码缩短。

### 7.1 主要源码位置

- `src/index.js`：Host 入口；`src/client.cjs`、`src/ui.css`：Web UI 源码。
- `lib/server.cjs`：插件管理 API；`lib/remote.cjs`、`lib/operations.cjs`：传输与远程操作。
- `lib/agent-scope.cjs`、`lib/connection-gate.cjs`、`lib/binding-trust.cjs`：可信会话、连接审批与绑定凭据。
- `lib/transfer-sessions.cjs`、`lib/cleanup.cjs`：分块传输会话和私有数据清理。
- `scripts/build.mjs` 生成 `lib/index.js`、`lib/client.js`。修改源代码时不要直接编辑生成入口。

Host-only 包不包含 Web Client；实验 UI 包采用独立构建。插件管理 Web API 的调用者身份仍依赖宿主提供的可靠鉴权和请求隔离，不应把固定确认字符串当作身份认证。

## 10. 常见问题与已知限制

**问：普通聊天能否填服务器 ID 让 AI 连接？** 不能。远程 AI 工具必须有可信绑定和相应审批。

**问：FTP/FTPS 能不能执行 Shell？** 不能，它们只提供文件能力；SSH 管理能力需要 SSH/SFTP 连接。

**问：为什么拖放文件没有开始上传？** 请确认已进入正确目录并拖进文件页的指定上传区域。文件夹递归拖放尚未支持。

**问：点击取消后还可能有文件吗？** 有可能。取消仅终止可中止的后续步骤，不会自动撤销已提交的远程修改或用户已保存的数据。

**问：停用/卸载是否清除所有痕迹？** 不会，且不应擅自删除远程服务器文件、用户下载文件和其他系统数据。

**问：能否在公司实验室免费评估？** 不能。新版许可证禁止所有组织性使用，包括免费内部评估。

**问：能否直接以 MIT 发布此新版本？** 不能用项目自身限制性许可证宣传 OSI 开源；第三方库仍保留它们各自的 MIT/Apache/BSD 等许可证。

**问：自动化测试通过是否可以立即生产使用？** 不能。本项目本身禁止商业/组织生产使用，实际环境安全性也仍需要验证。
